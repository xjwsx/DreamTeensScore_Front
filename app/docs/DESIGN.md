# 틴즈 캠프 팀 점수 웹앱 — 설계 문서

**대상:** 초등 6학년 ~ 고등 3학년 · 도장판을 대체하는 실시간 팀 점수 시스템
**버전:** v3 (확정 기술 스택 반영) · 2026-07-03

---

## 1. 개요와 목표

종이 도장판을 인쇄해 미션마다 도장을 찍던 방식을 대체해, 팀별 점수를 실시간으로 관리하는 웹앱을 만든다. 준비가 간편하고, 순위가 즉시 반영되며, 분실·훼손 걱정이 없다.

### 핵심 흐름 (확정)

1. 리더(관리자)가 캠프 전에 게임을 미리 설정한다 — 게임 개수, 각 게임 이름, 게임당 점수.
2. 게임마다 담당 스태프가 배정된다.
3. 스태프는 자기가 맡은 게임을 성공한 팀을 선택해 점수를 부여한다.
4. 모든 기기(리더 폰·스태프 폰·프로젝터 순위판)에서 점수가 실시간으로 갱신된다.

### 핵심 요구사항

| 항목 | 결정 내용 |
|------|-----------|
| 게임·점수 설정 | 리더(관리자)가 사전에 게임 목록과 게임당 점수를 등록 |
| 점수 입력 권한 | 게임별 스태프가 담당 게임의 성공 팀에만 부여. 참가자는 순위만 열람 |
| 실시간 공유 | 필요. 여러 기기에서 동시에 같은 점수판 열람 |
| 팀 규모 | 다팀(10팀 이상 확장 가능) |
| 점수 방식 | 게임당 고정 점수 기본. 순위별 차등(1·2·3등) 및 감점은 선택 옵션 |
| 기술 스택 | React·TypeScript·Vite·styled-components / Supabase / Vercel 배포 |

### 설계 원칙

- **단순함 우선** — 스태프는 폰에서 성공한 팀만 골라 탭하면 끝(3초 내).
- **실시간** — 점수를 주면 프로젝터 순위판이 즉시 갱신된다.
- **실수 방지·복구** — 스태프는 담당 게임만 다루고, 잘못 준 점수는 즉시 취소 가능.
- **저비용·무설치** — 앱 설치 없이 링크로 접속. 무료 등급 내 운영 가능.

## 2. 사용자 역할과 권한

| 역할 | 할 수 있는 일 | 접근 방식 |
|------|---------------|-----------|
| 관리자 (리더) | 게임 생성·점수 설정, 팀 등록, 스태프 배정, 점수 정정, 전체 기록 열람 | 관리자 PIN 로그인 |
| 스태프 (게임 진행) | 배정된 게임에서 성공한 팀에 점수 부여·취소 | 게임별 PIN 또는 코드 |
| 뷰어 (참가자·화면) | 실시간 순위판 열람만 가능. 입력 불가 | 공개 링크(로그인 불필요) |

> 핵심: 스태프는 '담당 게임'에만 접근한다. 예) 보물찾기 스태프는 보물찾기 점수만 부여할 수 있어 오입력이 원천 차단된다.

## 3. 게임과 점수 설정

리더가 캠프 전에 게임을 등록한다. 각 게임은 이름, 점수, 담당 스태프를 가진다.

### 점수 방식

| 방식 | 설명 (예시) |
|------|-------------|
| 고정 점수 (기본) | 성공한 팀 모두 같은 점수. 예) '퀴즈 성공 = +30' |
| 순위별 차등 (선택) | 등수마다 다른 점수. 예) '릴레이 1등 +50, 2등 +30, 3등 +10' |

> 감점 게임(페널티)도 같은 구조로, 음수 점수를 가진 게임으로 등록하면 된다. 예) '지각 = −10'.

### 게임 설정 예시

| 게임 이름 | 점수 | 담당 스태프 | 비고 |
|-----------|------|-------------|------|
| 보물찾기 | +50 | 김집사 | 성공 팀 모두 동일 |
| 성경 퀴즈 | +30 | 이전도사 | 고정 점수 |
| 릴레이 경주 | 1등+50 / 2등+30 / 3등+10 | 박선생 | 순위별 차등 |
| 찬양 미션 | +20 | 최청년 | 고정 점수 |
| 지각 페널티 | −10 | 리더 공통 | 감점 |

### 설정 규칙

- 게임 개수·이름·점수는 리더가 자유롭게 추가·수정·삭제(캠프 시작 전·중 모두 가능).
- 한 게임에 여러 스태프를 배정할 수 있음(교대·분업).
- 같은 게임을 한 팀에 중복 부여하지 못하도록 '팀당 1회' 잠금을 게임별로 켤 수 있음.

## 4. 데이터 모델

실시간 동기화에 적합한 구조. Supabase(Postgres) 기준 4개 테이블. 팀 총점은 점수 기록을 합산하되, 성능을 위해 팀 레코드에 캐시한다.

> DB 컬럼은 snake_case, 프론트 타입(`src/types`)은 camelCase로 매핑한다. 실제 스키마는 `app/supabase/schema.sql` 참고.

### teams (팀)

| 필드 | 타입 | 설명 |
|------|------|------|
| id | uuid | 팀 고유 ID |
| name | text | 팀 이름 (예: 사자팀) |
| color | text | 순위판 색상 |
| total_score | integer | 총점 캐시 (실시간 갱신) |

### games (게임)

| 필드 | 타입 | 설명 |
|------|------|------|
| id | uuid | 게임 ID |
| name | text | 게임 이름 (예: 보물찾기) |
| score_mode | text | fixed \| ranked (고정 / 순위별) |
| points | integer | 고정 점수 (감점은 음수) |
| rank_points | integer[] | 순위별 점수 [50,30,10] (ranked일 때) |
| staff_ids | uuid[] | 담당 스태프 ID 목록 |
| once_per_team | boolean | 팀당 1회 제한 여부 |
| active | boolean | 현재 진행 가능 여부 |

### score_entries (점수 기록 / 감사 로그)

| 필드 | 타입 | 설명 |
|------|------|------|
| id | uuid | 기록 ID |
| team_id | uuid | 대상 팀 |
| game_id | uuid | 적용 게임 |
| points | integer | 실제 부여 점수 |
| rank | integer | 등수 (ranked일 때, 선택) |
| created_by | uuid | 부여한 스태프 ID |
| created_at | timestamptz | 부여 시각 |
| voided | boolean | 취소 여부 |

### users (관리자·스태프)

| 필드 | 타입 | 설명 |
|------|------|------|
| id | uuid | 사용자 ID |
| name | text | 이름 |
| role | text | admin \| staff |
| pin_hash | text | PIN 해시 (평문 저장 금지) |
| game_scope | uuid[] | 담당 게임 범위 (스태프) |

## 5. 화면 구성

모바일 우선(스태프·리더용)과 대형 화면(순위판)을 함께 고려한다.

| 경로 | 화면 | 대상 |
|------|------|------|
| `/scoreboard` | 실시간 순위판 (기본) | 뷰어 · 프로젝터 (가로) |
| `/login` | 스태프 · 리더 로그인 | 스태프 · 리더 |
| `/staff` | 스태프 점수 부여 (핵심) | 스태프 |
| `/staff/history` | 스태프 부여 내역 | 스태프 |
| `/admin` | 관리자 게임 설정 콘솔 | 관리자 |

### 5-1. 실시간 순위판 (뷰어 · 프로젝터)

- 팀별 총점을 큰 카드/막대그래프로 표시, 1·2·3위 강조. 점수 변동 시 애니메이션으로 재정렬.
- 상단에 캠프 이름·시각, 하단에 최근 점수 부여 티커(선택).

### 5-2. 리더(관리자) 콘솔

- 게임 등록·점수 설정(고정/순위별), 팀 등록, 스태프 배정.
- 전체 점수 기록 열람·정정, 캠프 초기화, 결과 발표 화면 트리거.

### 5-3. 스태프 점수 부여 화면 (핵심)

- 로그인하면 담당 게임이 바로 열림(게임이 여러 개면 게임 선택).
- 고정 점수: 성공한 팀을 탭 → 점수 자동 부여. 여러 팀 연속 선택 가능.
- 순위별: 1등·2등·3등 팀을 지정 → 각 등수 점수 자동 부여.
- 부여 직후 '방금 준 점수' 카드에서 즉시 취소(Undo).

### 5-4. 스태프 부여 내역

- 본인이 담당 게임에서 준 점수 목록과 취소 기능(정정용).

> 화면 디자인은 iOS 네이티브 컨셉. 클로드 디자인 프롬프트는 `화면디자인_프롬프트_iOS컨셉.md` 참고.

## 6. 기술 스택 (확정)

프론트엔드는 React + TypeScript + Vite로 개발하고 styled-components로 스타일링한다. 백엔드는 Supabase(Postgres + Realtime)를 사용하며, 프론트엔드는 Vercel에 배포한다.

| 구성 요소 | 확정 기술 |
|-----------|-----------|
| 언어·프레임워크 | React + TypeScript |
| 빌드 도구 | Vite |
| 스타일링 | styled-components |
| 백엔드·실시간 DB | Supabase (Postgres) |
| 인증 | PIN 기반 검증 (스태프·관리자). 뷰어는 로그인 불필요 |
| 프론트 배포 | Vercel |

### 6-1. 프로젝트 구조

```
src/
  pages/       화면 (Login, Scoreboard, StaffScoring, StaffHistory, AdminConsole)
  components/  재사용 UI 컴포넌트 (styled-components)
  lib/         Supabase 클라이언트 초기화
  hooks/       실시간 데이터 훅 (useTeams, useGames)
  types/       데이터 모델 타입 (Team, Game, ScoreEntry, User)
  styles/      테마 · 전역 스타일 (ThemeProvider)
```

### 6-2. 실시간 동작 흐름

1. 스태프가 성공 팀에 점수 부여 → score_entries 추가 + 해당 팀 total_score 갱신.
2. Supabase Realtime 구독이 변경을 감지 → 모든 화면에 자동 푸시.
3. 순위판이 `useTeams` 훅으로 자동 재정렬·표시(수동 새로고침 불필요).

### 6-3. 보안·권한 요점

- 뷰어 링크는 읽기 전용 — Row Level Security(RLS)가 서버단에서 쓰기를 차단.
- 스태프는 game_scope로 담당 게임에만 점수 부여 가능.
- PIN은 해시로 저장하고, Supabase 키는 환경변수로 관리(Vercel 환경변수).
- 모든 점수 변경은 로그로 남아 사후 추적·정정 가능.

> 현재 `schema.sql`의 RLS는 개발 편의를 위해 전부 허용 상태. 운영 전 반드시 위 규칙으로 강화할 것.

## 7. 개발 로드맵

| 단계 | 범위 | 산출물 |
|------|------|--------|
| MVP (1주) | 게임·점수 리더 설정, 스태프 성공 팀 부여(고정 점수), 실시간 순위판 | 캠프에서 바로 쓸 최소 버전 |
| v1 (2~3주) | 순위별 차등·감점, PIN 인증·게임별 스태프 배정, 취소·정정 | 안정적 운영 버전 |
| v2 (이후) | 결과 발표 애니메이션, 통계·리포트, 다중 캠프 | 재사용·확장 버전 |

## 8. 확장 아이디어

- **QR 코드 게임** — 각 게임 부스에 QR을 두고 스태프가 스캔해 자동 부여.
- **결과 발표 모드** — 하위 순위부터 극적으로 공개하는 카운트다운 화면.
- **배지·업적** — 특정 게임 만점 팀에 배지 부여.
- **캠프 후 리포트** — 팀별 점수 추이·게임별 통계 PDF 자동 생성.
- **도장판 향수** — 순위판에 옛 도장 느낌의 스탬프 아이콘으로 정서적 연결 유지.
